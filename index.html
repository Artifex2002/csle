06 / ENGINEERING JUDGMENT

The choices behind the build.

Practical emulation means making the boundaries explicit.

Read the design rationale ↗
01

Reuse the platform. Extend the industrial layer.

Build on CSLE’s existing infrastructure while adding OT-specific images, services, traffic, and topology.

02

Make the lab inspectable.

SSH and Linux diagnostics support management and data collection. They are practical lab interfaces, rather than exact replicas of vendor controller internals.

03

Model network conditions explicitly.

Configure delay, jitter, loss, and bandwidth for protocol nodes. These are experimental parameters; physical-process fidelity requires additional modeling and validation.

Implementation scope & source snapshot +

This case study describes the emulation_OT branch at commit 3b590abe. It distinguishes code additions and configured infrastructure from verified runtime outcomes.

The snapshot has remaining integration work: missing OT traffic-command mappings, an S7 image-constant mismatch, a declared combined-protocol image without build files, and a Modbus example helper dependency. The inherited vulnerability and observation configuration also needs alignment with the new topology.

The source supports a protocol-level OT extension. It does not establish a validated physical-process digital twin, certified industrial security, or measured OT-specific reinforcement-learning performance.
